Meadow Grove Church App

A church “home base” that leaders can update without an App Store release: services, events, announcements, and a moderated prayer wall — one API for iOS and a companion website.

Problem

A church needs one place for service times, classes, events, and announcements — and leaders need to change that content themselves. Static apps go stale. Meadow Grove treats the home screen as a CMS: sections and cards live on the server, with a draft → publish path and push when something new goes live.

Architecture

The iOS client is SwiftUI (tabs: Home, Announcements, Prayer, Profile). Auth and role flags are stored in AppStorage. Almost all content is remote. Backend.swift talks to a FastAPI service on Render (meadowgrove.onrender.com) using an X-User-Id header. The backend uses SQLAlchemy + Postgres (SQLite locally), bcrypt passwords, SendGrid email, and APNs for push.

Client (SwiftUI) ↔ FastAPI ↔ Postgres
Side channels: APNs (announcements, card publish, prayer approval) and SendGrid (password reset, leader-code requests).

What members see

Dynamic home

A sheet-style home feed loads sections and cards from the API — service times, classes, outreach, events, pastor message. Cards open a detail page with time, location, age group, and notes.

Announcements

New / old filter, detail view, optional link to a home card. Unread counts show on the tab and app icon.

Prayer requests

Submit with visibility (everyone or leaders only) and an anonymous option. “I’m praying” increments a live count. Approved requests stay active for seven days.

Follow events

Members can follow a class or event. Later updates notify followers only, not the whole church.

What leaders can do

Leader access is gated by an invite code (request emails me; the code is redeemed at signup). Leaders can create, edit, archive, and publish cards; post and archive announcements; approve or deny prayer requests; and edit the home header photo. Unpublished cards stay hidden until they pass server-side validation. Publishing can auto-create an announcement and fire a push.

Backend surface

The FastAPI app covers users and login, password reset, leader codes, home sections/cards (CRUD, publish, archive, follow), announcements, prayer (submit, approve/deny, pray-toggle), and device-token registration. A companion vanilla JS site in website verson/ reads the same home and announcement endpoints.

Polish

Branded splash until home content loads, a multi-step onboarding tour, appearance settings, legal pages, support/bug email, account deletion, and an App Store update checker. Home and Profile work as a guest; Announcements and Prayer require sign-in.
